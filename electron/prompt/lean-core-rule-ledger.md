# Lean core rule ledger

Audit trail for the `leanCore` flag (stage B). Source of truth for the old text is
`electron/prompt/sections/behavior-core.ts` (`MARSHAL_BEHAVIOR_CORE`, unchanged and still used
when the flag is off). The new text is `electron/prompt/sections/lean-behavior-core.ts`
(`LEAN_BEHAVIOR_CORE`). Deeper trims of the claude-tooling, host-tools and runtime sections live in
`electron/prompt/sections/lean-deep-sections.ts` and apply only when `leanPrompt` and `leanCore`
are both on.

Method: every distinct rule, hard constraint, and precedence/authorization/safety rule was kept.
Only wording, repeated examples, cross-references to section names, and restatements were removed.
`electron/prompt/lean-core.test.ts` pins about 50 anchor phrases (one or more per old section) and
asserts that every old heading below appears in this ledger.

## 3. Semantic differences to review

1. **Yielding while children run.** Legacy core: "Do not yield your turn while children are still running unless the user asks." Legacy host-tools "Waiting": "End your turn... Marshal wakes you when the child reports." These contradicted each other. The lean core now says: do not yield while a child still needs your coordination; when only waiting on children remains, end the turn; before the final result, account for every child. This is the change the "end the turn after delegating" request asked for.
2. **Parameter lists.** The deep host-tools trims drop tool parameter lists that the tool schemas already carry (checked against the `spawnSubagent`, `createAutomation`, `askUser`, and `messageSubagent` schemas). Deferred tools load their schema through ToolSearch before use; a session with a tool-less surface never sees these sections.
